FizzBuzz — why order of conditions matters

Same conditions, different order. One produces the wrong answer for N=30. Step through both and see why.
INPUT N
APPROACH 1 checks divisibility-by-3 first
if (A % 3 == 0) {
print("Fizz");
} else if (A % 5 == 0) {
print("Buzz");
} else if (A % 3 == 0 && A % 5 == 0) {
print("Fizz-Buzz"); // unreachable for N=30
}
A % 3 == 0
—
A % 5 == 0
—
A % 3 == 0 && A % 5 == 0

APPROACH 2 checks the most-specific case first
if (A % 3 == 0 && A % 5 == 0) {
print("Fizz-Buzz");
} else if (A % 5 == 0) {
print("Buzz");
} else if (A % 3 == 0) {
print("Fizz");
}
A % 3 == 0 && A % 5 == 0
—
A % 5 == 0
—
A % 3 == 0
—
OUTPUT
—
Lesson → if-else conditions fire top to bottom. The first match wins, the rest never run. So when conditions overlap (a multiple of 15 is also a multiple of 3 and of 5), put the most specific check first.
